## ⚠ 必读：数据处理流程

核心流程：

**行来源 = 六个公司的车管基础数据（则一/盛丰/胜途/富海源/拓达/荣欣）**。每条派车记录=报表的一行，自带邮路名称、车牌号、车厢码、邮路执行日期、派车单号、运输量。承运单位由文件名经 company-map.json 映射。


**四个产出格式**：
- **车型汇总表（Step 1）**：草滩+港务两个在线表当月Sheet合并，跨场地补容间（串行：草滩记录→港务测量值），保留场地来源。交付产物①，也是初版的容积来源
- **基础报表初版（固定 21 列）**：供人工核对，保留容间原始精度，并使用红/橙/黄/蓝四色标记、问题汇总和结构发现。蓝=串行跨站点取容积，橙=完全未测量，黄=跨档，红=缺失
- **基础报表拆分正式版（Step 7）按模板逐 Sheet 输出**：常规 Sheet 实测有 17 列和 18 列两种，容间取整数，不得把初版的 21 列直接套过去
- **盈亏表（Step 8）按最近一个有效月份 Sheet 取结构**：车型组、路线顺序、列数和底部环比区都从模板动态读取，不能拿工作簿第一张旧月份 Sheet

业务细节：
- 盈亏表底部有**环比区**（上月/本月/环比%）
- 模板路线顺序固定，照搬不能改

## ⚠ 容积取数规则（重要）

**行来源 = 车管数据（每条派车=一行），容积从在线表（草滩+港务合并）取**。

取数优先级：
1. (派车日期+车牌)精确匹配在线表 → 取非零容积
2. 没匹配上 → 同车牌在在线表任意站点/任意日期的非零容积（串行跨站点取，取到后标蓝"串行"标注）
3. 都没有 → 标橙"未测量"

**任何不确定必标注**（核心铁律）：所有标注进问题汇总Sheet，按类型分组+建议动作+处理结果列，供人工二次审核。匹配键严格用(日期+车牌)，不用"出现顺序"。

## 对话流程

### 开场（先识别意图）

用户提到"邮局报表""委办报表""基础报表""盈亏表"等关键词时：

1. **要几月？**（如"4月"）
2. **要哪个产出？**（车型汇总表 / 初版 / 拆分 / 盈亏）

用户说"做X月报表"这种笼统的话 → 默认从**车型汇总表**开始，顺序跑完全部。

### 收集文件

按对应入口的文件清单，**一次只问一个**。用户给完一个，确认收到后再问下一个。

### 闸门规则

- 初版生成后 → **立即停止**，汇报自检指标和问题数，提示用户去核对
- 拆分/盈亏请求 → **先问"初版核对过了吗？请提供核对修正后的初版文件"**，没有则不执行

## 路径规则（必须遵守）

- AgentOS **没有 `/inputs` 和 `/outputs`**。用户上传的文件在 `/workspace/<文件名>`，输出写 `/workspace/output`。
- 处理前先列目录确认真实文件名：`print(os.listdir('/workspace'))`，**不要臆造或拼错文件名**。
- 报 `PermissionError: '/outputs/...'` → 输出目录传错，改 `/workspace/output`。
- 报 `FileNotFoundError: '/inputs/...'` → 输入路径传错，按脚本打印的目录清单改正。
- 调用自带容错的脚本时，看到 `[STOP]` 必须改正路径重跑，不要原样重试。

### 4. 拿不准就标注（核心）

**留空比编造强一百倍**。任何无法确定的字段：

- 留空
- 在备注列写明原因："价格表未覆盖：路线「西安-湛江」未找到" / "调度通知覆盖" / "两车合并" / "数据变动待确认"
- 进问题汇总 Sheet 让人核对

参照邮局官方备注风格：`调度通知按30吨结算` / `往返邮路` / `两辆12吨车合并为一辆40A的车`。

### 5. 关键节点问用户

遇到以下情况**停下来问**，不要自作主张：

- 路线归类歧义（如"固原"该进哪个 Sheet）
- 价格表/基准表结构和往常不同
- 备注列出现陌生的业务术语
- 用户给的文件不全或格式异常
- 多种合理处理方案

建议使用具备工具调用、长上下文和代码执行能力的中高端模型（如 Claude Sonnet/Opus、GPT-4o 及同等级模型）。弱模型容易在以下环节失效：跨文件匹配、模板版本选择、路线歧义判断、异常回溯。无论模型多强，人工闸门约束结果，不能只相信提示词。

## 已知坑位

| 坑 | 解法 |
|------|------|
| 草滩 vs 港务列名不同 | 关键词表同时覆盖 |
| 草滩容积大量为空（串行：港务发车→草滩记录） | 跨场地补容间：同车牌从港务取实测容积 |
| 系数当容积下限 | (limit,ton,coef)三值分开 |
| 上海东/西合并 | L6标准化归一 |
| 在线表匹配顺序不稳 | (日期+车牌)精确匹配 |
| **车型组按月变化** | **从当月模板表头动态读取** |
| **盈亏误取第一张旧月份Sheet** | **选择最后一个有效月份Sheet** |
| **初版与正式版格式混用** | **初版固定21列；拆分版逐Sheet照搬17/18列** |
| **固原两个Sheet共存** | **照官方模板同时保留** |
| **`max_column`被历史空列污染** | **动态发现列数时只数非空表头，不信 `max_column`** |
| **新业务标注** | **不懂就留空+问用户** |
