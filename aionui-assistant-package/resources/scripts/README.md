# Skill: 生成基础报表初版

触发：用户要"初版""核对报表""生成初版""做X月报表（无明确产出）"。

## ⚠ 执行约束（铁律）

推荐操作序列：

1. 收集文件
2. 运行 `scripts/inspect_sources.py` 探查结构
3. 运行 `scripts/build_draft.py`
4. 运行 `scripts/verify_draft.py` 并抽样回查
5. 把经脚本或 Excel 验证的指标汇报给用户

脚本是确定性工具，不是黑盒。允许用 Python 读取 xlsx 做结构探查、异常回溯和验证；禁止在没有证据时凭感觉改金额或绕过人工闸门。

## 你需要向用户收集的文件（一次一个）

| # | 文件 | 用途 |
|:--:|------|------|
| 1 | 草滩在线容积测量表 | 提取车辆容间（Sheet名 M月D日） |
| 2 | 港务在线容积测量表 | 提取车辆容间（Sheet名 M.D） |
| 3 | 车型基准表（N月车型.xlsx） | 当月车辆清单 |
| 4 | 一干价格表 | 一干路线运价（单程/往返/草滩） |
| 5 | 二干价格表 | 二干路线运价 + 判定一干/二干 |
| 6 | 车管基础数据目录 | 各公司 .xlsx |

**还需要**：月份（如 4）和输出目录。

## 执行命令

文件收齐后，先定位扩展目录 `<EXT_DIR>`（见助手 context.md），然后：

```bash
python3 <EXT_DIR>/scripts/build_draft.py <月份> <输出目录> \
  <草滩表> <港务表> <车型表> <一干价格表> <二干价格表> <车管目录>
```

**Windows** 下如果 `python3` 不存在，回退用 `python`。

## 脚本会做什么

1. 提取合并在线表（草滩+港务，动态找表头，按关键词定位列）
2. 基准表分类 + 容间取用（基准表为准，补量按日期+车牌精确匹配）
3. 价格表动态解析 + 吨位判定（独立于价格匹配）
4. 价格匹配（路线标准化 L0-L6，运价=系数×标准价）
5. 车管匹配
6. 生成初版（结构发现 + 问题汇总 + 基础报表，红/橙/黄标色）

## 输出

`<输出目录>/N月_02_基础报表初版.xlsx`，三个 Sheet：

- **结构发现**：本次动态识别的各源文件结构。人工核对**先看这一页**。
- **问题汇总**：所有需人工核对的行。
- **基础报表**：21 列 v1.16 数据。

## ⛔ 立即停止

汇报完后**不要继续**拆分或盈亏。提示用户：

> 初版已生成。请打开「问题汇总」Sheet 逐条核对，并在「处理结果」列标注。核对完成后再告诉我"拆分"或"盈亏"继续。

## 可选：和基准版对比

如果用户提供了基准版路径，可跑验证脚本：

```bash
python3 <EXT_DIR>/scripts/verify.py <本次输出> <基准版>
```

它会对比关键指标，全 ✅ 即结果与基准一致。

全链路回归：

```bash
python3 <EXT_DIR>/scripts/test_runner.py
```

该测试会验证 21 列初版基准、拆分 17/18 列模板与行数守恒、盈亏最近月份模板/车型组/路线顺序/环比区。

## 自检异常处理

异常时先用结构探查、案例库和源文件回查原因。可逆且证据充分的脚本问题可以修复并重跑回归；涉及业务口径或多种合理方案时停止询问用户：

| 指标 | 标准 | 异常查什么 |
|------|:--:|------|
| 合并数 vs 基准数 | 差距<10% | Sheet 月份过滤 |
| 缺失率 | <5% | 车牌匹配键 |
| 未测量率 | <2% | 回在线表回查逻辑 |
| 跨档率 | 1%-5% | 频率统计、系数赋值 |
| 价格匹配率 | >90% | 路线标准化、Sheet选择 |
| 车管匹配率 | >95% | (车牌+挂车)匹配 |
