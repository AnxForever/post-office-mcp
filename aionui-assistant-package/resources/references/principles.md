# 设计原则

## 核心理念

**不追求 100% 正确，重点是遇到不确定/可能有问题的及时标注，方便人工二次核对。**

## 五条铁律

1. **脚本做粗活** — 确定性逻辑用 Python 脚本跑
2. **自己补判断** — 识别异常、对比历史、追查可疑项
3. **不确定就查** — 跑 Python 读源数据验证，不凭记忆
4. **拿不准就标注** — 留空+备注写明原因，进问题汇总
5. **关键节点问用户** — 路线歧义、陌生术语、文件不全

## 架构约束

- **行来源必须用车管数据**，不能用在线表或车型表
- **初版固定 21 列**，列数只数非空表头
- **容积取数**：(日期+车牌)精确 → 同车牌跨站兜底 → 标橙
- **价格表全动态读取**：吨位档/系数/路线不写死
- **人工闸门**：初版后立即停止，拆分/盈亏等核对

## 颜色标注体系

| 颜色 | 色值 | 含义 |
|------|------|------|
| 红 | #FF6666 | 数据缺失 |
| 橙 | #FFA500 | 未测量 |
