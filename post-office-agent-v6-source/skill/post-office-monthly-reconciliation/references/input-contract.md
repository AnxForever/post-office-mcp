# 输入契约

## 模式 A：仅车型汇总

必须提供目标月 `YYYY-MM` 以及两个工作簿：

- 草滩在线测量表1个，日 Sheet 名如 `4月1日`。
- 港务在线测量表1个，日 Sheet 名如 `4.1`。

在线表必须可发现邮路、车牌、挂车和容积字段。草滩容积公式没有缓存值时，必须可发现长、宽、高。
容积统一按四舍五入取整后的整数参与车型和吨位匹配。车型汇总的“容积取证”Sheet记录
源文件、Sheet、行号、容积单元格、原公式、长宽高、取整前结果、取整规则和最终容积。

## 模式 B：完整月度流程

当 `company-map.json` 保持默认6家公司时，阶段一需要上传9个动态工作簿
（草滩、港务、6份车管、财务）；**三份版式模板和两份合同价格表随 Skill 内置，不必每月上传**：

| 角色 | 数量 | 必需结构 |
|---|---:|---|
| 草滩在线测量表 | 1 | 目标月日 Sheet；邮路、车牌、挂车、容积 |
| 港务在线测量表 | 1 | 目标月日 Sheet；邮路、车牌、挂车、容积 |
| 车管基础数据 | 按公司映射 | 邮路名称、邮路执行日期、派车单号、车牌号、车厢码/挂车号、邮运量、结算吨位 |
| 财务收入表 | 1 | 邮路名称、额定/结算吨位、结算收入、普服收入。**客户可能命名为 `YYYY.MM运输局.xlsx`，与 `YYYY.MM财务收入表.xlsx` 是同一张表** |
| 一干价格表 | 1 | 路线、公里、吨位、容积下限、系数、标准价 |
| 二干价格表 | 1 | 同上 |

车管文件数量等于 `company-map.json` 中的公司数，每家正好1个。新增公司时先增加公司映射，不修改业务代码。

### 内置模板与价格表（上传可选）

| 角色 | 内置资产 | 作用 |
|---|---|---|
| 基础报表初版模板 | `assets/draft-template.xlsx` | 21列表头 |
| 一干委办盈亏模板 | `assets/first-profit-template.xlsx` | 月份页、7列吨位分组、路线和合计行 |
| 二干委办盈亏模板 | `assets/second-profit-template.xlsx` | 同上 |
| 一干价格表 | `assets/first-price-table.xlsx` | 一干 2026 版：每 5 m³ 一个折算系数 |
| 二干价格表 | `assets/second-price-table.xlsx` | 二干 2026 合同价：吨位档 + 系数行 |

**上传了以客户上传的为准**（客户换版式或调价时不必改包）；没上传直接用内置版本，
且内置版本不参与目标月份推断。内置文件齐全时，这两类角色不算缺文件。

一干/二干成套使用：用户只传了其中一份，或传了一份识别不出一干/二干的候选时，
**不会**用内置的另一份补齐——两版合同混用不会报错，只会算错。此时照常返回
`status:"needs_input"`，请用户把两份一起上传。

价格表是合同，很少变动；一旦调价，除了让用户上传新版，还要同步替换 `assets/` 里的文件重新打包。

文件名只作辅助信号，以工作表结构和字段为准。输入损坏、角色冲突、必需字段缺失、公司映射缺失或目标月份不一致必须阻断。

## 角色识别方式

执行 `--phase detect --task review|summary|profit` 时，所有工作簿先按结构分类：

| 角色 | 结构依据 |
|---|---|
| 草滩在线测量表 | 日 Sheet 名形如 `8月1日` |
| 港务在线测量表 | 日 Sheet 名形如 `8.1` |
| 车管基础数据 | 邮路名称 + 邮路执行日期 + 派车单号 + 邮运量 |
| 财务收入表 | 邮路名称 + 结算收入 + 普服收入 |
| 基础报表原版 | 含 Sheet `一干汇总` 或 `二干基础` |
| 基础报表初版模板 | 21 列表头完全匹配 |
| 价格表 | 路线/路向 + 公里 + 吨位/系数，且无车牌号/派车单号等单车字段 |
| 盈亏模板 | 7 列吨位分组子表头 |

一干/二干层面无法只靠表结构区分：一干 2025 版模板也有 8 吨档，二干 2026 版价格表也有 40B 档。
脚本按「表内标题 → 文件名」的顺序判断；两者都没有时返回 `price_candidate` / `profit_candidate`
并标记 `low`，必须由人工确认，不得按档位名猜测。

如果两份在线表使用同一种日 Sheet 命名，脚本无法确定站点，会标记 `low` 并要求人工确认。

## 阶段二输入

- 必须保留阶段一生成的 `output/run-state.json`。
- 必须上传人工核对后的 `{M}月_02_基础报表初版.xlsx`。
- 可选上传上月一干和二干盈亏表，用于生成环比。

人工可修正容间、价格等核对字段，但不得改变行数、行顺序及车管权威字段（承运单位、派车单号、邮路、执行日期、车牌和挂车）。修订容间后，脚本重算吨位、系数、标准价、运价和跨档。

## 模式 C：仅盈亏表

不建立 `run-state.json`，可与完整流程分开单独执行。**当月源数据是第一基准**：
吨位档、路线顺序和全部数值都由下列两份文件决定，盈亏模板可选。

必需输入（2 份）：

| 输入 | 数量 | 必需结构 |
|---|---:|---|
| 基础报表原版 | 1 | 含「一干汇总」「二干基础」；邮路名称、车牌号、封车时间、吨位、运输量、运价 |
| 财务收入表 | 1 | 表头第 1 行；邮路级别、自委办、往返、邮路名称、流水号、车牌号、额定吨位、结算收入、普服收入。**`YYYY.MM运输局.xlsx` 与 `YYYY.MM财务收入表.xlsx` 是同一张表，31 列完全一致** |

可选输入：

| 输入 | 作用 |
|---|---|
| `--tpl-dir` 盈亏模板目录 | 只追加「当月无数据的历史路线」占位行，不改变吨位档和数值 |
| `--no-template-routes` | 不追加占位，只输出当月实际出现的路线 |

「一干汇总」有两个“邮路名称”列时，后一列是已标准化的路线，优先使用它。
「两趟合一趟」「降吨位」等特殊 Sheet 的记录已包含在一干汇总/二干基础内，不额外计入。
上月盈亏表可选；未提供则环比区留空。

## Skill 静态资产

- `assets/split-report-template.xlsx`：拆分版母版。
- `assets/draft-template.xlsx`：21列基础报表初版模板。
- `assets/first-profit-template.xlsx`、`assets/second-profit-template.xlsx`：一干/二干盈亏模板。
- `assets/first-price-table.xlsx`、`assets/second-price-table.xlsx`：一干/二干合同价格表（2026 版）。
- `assets/company-map.json`：车管文件名公司代号到全称的映射。
- `assets/route-aliases.json`：显式路线别名及一干/二干归属。

阶段一将所有动态源文件、模板布局和静态资产的 SHA-256 写入运行状态。阶段二任一锁定文件缺失或变更时必须阻断。
