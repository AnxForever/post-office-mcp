# 邮局一干/二干盈亏表

只运行本技能里的 `agentos_entrypoint.py`，不要自己写临时脚本、不要自己读写 Excel、不要自己算金额。

## 输入只有两份文件

1. **基础报表原版** —— 含「一干汇总」和「二干基础」两个工作表
2. **财务收入表** —— 表头同时有「结算收入」「普服收入」（客户常叫「运输局」）

**不需要价格表、不需要盈亏模板、不需要车管数据。** 价格表与这张盈亏表无关。

按表结构识别文件，不看文件名。识别不出或有多个候选时，把候选列给用户确认，不要自己挑。

## 一条命令做完

```python
import runpy, sys
sys.path.insert(0, "{skill_dir}/scripts")
sys.argv = ["agentos_entrypoint.py", "--phase", "profit", "--workspace", "/workspace"]
runpy.run_path("{skill_dir}/scripts/agentos_entrypoint.py", run_name="__main__")
```

- 不传 `--month`：脚本从基础报表的业务日期推断目标月。
- 返回 `status:"profit_completed"` 就是做完了，**立刻汇报，不要重跑，也不要再执行任何脚本**
  （平台会把连续相同的工具结果判为空转并中止任务）。
- 返回 `status:"needs_input"`：把 `missing_inputs[].action` 逐条告诉用户，不是脚本报错。
- 返回 `status:"needs_month"`：用大白话问一句是哪个月，拿到答复再执行（用 `--month 2026-09`）。

## 表长什么样

- 每行一条邮路；横向每档 7 列：趟次、装载量、每车平均装载量、运费、结算收入、盈亏值、平均每车盈亏
- 最右 4 列是这一行的合计：趟次、委办运费、结算收入、总盈亏
- 表底「上月 / 本月 / 环比」没有上月表时留空，不猜
- **第二页「问题清单」**：收入没配上的趟次、一干/二干改判的邮路、口径说明

## 分档规则（客户 2026-10 书面确认）

权重下来一份：基础报表的「容间」列按区间分档，表头就是区间名。

| 容间（m³） | 表头档位 |
|---|---|
| < 55 | 小于55 |
| 55 – 100 | [55,100) |
| 100 – 130 | [100,130) |
| 130 – 150 | [130,150) |
| 150 – 180 | [150,180) |
| ≥ 180 | 大于180 |

- 180 整按「大于180」处理。
- 基础报表里的「吨位」列即使存在也不参与分组——分组只看容间。
- 容间为空的记录不参与出表，会在诊断信息里体现。

## 各字段怎么来的

| 字段 | 来源 |
|---|---|
| 邮路名称 | 基础报表「邮路名称」 |
| 趟次 | 同邮路 + 同容间区间的基础报表行数 |
| 装载量 | 这些行「运输量 / 邮运量」求和 |
| 运费 | 这些行「运价」求和（运价是每趟已算好的运费总额） |
| 结算收入 | 财务表「结算收入 − 普服收入」，按车牌 + 日期逐趟配对 |
| 盈亏值 | 结算收入 − 运费 |

收入配对：车牌+日期完全一致 → 条数相等按日期顺序一一对应 → 7 天内最近日期贪心。
反向路线（`xx-西安`）不参与配对，按官方口径并入正向路线。

## 一干/二干归属

以财务收入表的「邮路级别」为准，基础报表 sheet 名只是兜底。改判的邮路会列在问题清单。

## 停下来的情况

| status | 含义 | 怎么跟用户说 |
|---|---|---|
| `month_mismatch` | 基础报表的业务日期比目标月旧，文件没更新 | 原样转述 message，不要换文件硬跑 |
| `unreadable_base` | 缺少必要列 | 把缺的列名说清楚，请用户补表 |
| `empty_base` | 一行有效数据都没读到 | 请用户确认文件对不对 |
| `finance_mismatch` | 一半以上派车记录配不上收入，两份文件很可能不是同月 | 请用户确认两份文件是不是同一个月的 |

月份规则：数据月份比目标月**新**（文件名写错）时照常出表，`month_note` 会说明实际用的是哪个月。
