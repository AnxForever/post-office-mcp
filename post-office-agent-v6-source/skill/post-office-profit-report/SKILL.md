# 邮局一干/二干盈亏表

只运行本技能里的 `agentos_entrypoint.py`，不要自己写临时脚本、不要自己读写 Excel、不要自己算金额。

## 输入只有两份文件

1. **基础报表原版** —— 含「一干汇总」和「二干基础」两个工作表。
   也可以直接上传上一阶段生成的 `N月_03_基础报表拆分版.xlsx`，它同样带这两个页签。
2. **财务收入表** —— 表头同时有「结算收入」「普服收入」（客户常叫「运输局」）

**不需要价格表、不需要盈亏模板、不需要车管数据。** 价格表与这张盈亏表无关。

按表结构识别文件，不看文件名。识别不出或有多个候选时，把候选列给用户确认，不要自己挑。

## 一条命令做完

```python
import runpy, sys
sys.path.insert(0, "{skill_dir}/scripts")
sys.argv = ["agentos_entrypoint.py", "--phase", "profit", "--workspace", "/workspace"]
runpy.run_path("{skill_dir}/scripts/agentos_entrypoint.py", run_name="__main__")
```

- 不传 `--month`：脚本从基础报表的业务日期推断目标月。
- 返回 `status:"profit_completed"` 就是做完了，**立刻汇报，不要重跑，也不要再执行任何脚本**
  （平台会把连续相同的工具结果判为空转并中止任务）。
- 返回 `status:"needs_input"`：把 `missing_inputs[].action` 逐条告诉用户，不是脚本报错。
- 返回 `status:"needs_month"`：用大白话问一句是哪个月，拿到答复再执行（用 `--month 2026-09`）。

用户改了基础报表或财务表要重跑时：输出目录已有 `N月_04_*.xlsx` 会返回 `output_exists`，
先问用户；确认覆盖带 `--force`，想保留旧版就换一个输出目录。

## 表长什么样

- 每行一条邮路；横向每档 7 列：趟次、装载量、每车平均装载量、运费、结算收入、盈亏值、平均每车盈亏
- 最右 4 列是这一行的合计：趟次、委办运费、结算收入、总盈亏
- 表底「上月 / 本月 / 环比」没有上月表时留空，不猜
- **第二页「问题清单」**：先按吨位/容间汇总（趟数、运费、收入、盈亏）；再列
  没配上收入的趟次、财务表里有收入但基础表没有对应派车的记录（这两类都不算进主表，
  留给人核对），以及一干/二干归属说明

## 交付前必须对平

脚本出表后会逐行复核：每条邮路的趟次/运费/收入相加 = 合计行 = 基础报表汇总。
对不上就返回 `reconciliation_failed` 并停住，不发布、不交付。
基础报表里如果有行既没吨位也没容间（分不出车型），返回 `base_rows_dropped` 停住，
不会静默丢行。收入没对上的趟次、没对到趟次的收入、基础表没有的车，都单独列问题清单，
保证「主表 + 问题清单 = 源数据」。

## 分档规则：看基础报表给了什么

**不按一干/二干写死。** 每张表按它实际带的列来分，客户给什么就用什么：

| 表里有什么 | 怎么分 |
|---|---|
| 有「吨位」列且有值 | 按吨位分车型（3 / 12 / 20 / 30 / 40（40A）/ 40B …） |
| 没有「吨位」列，或整列为空 | 按「容间」区间分（见下表） |
| 个别行没吨位、但有容间 | 按容间推回吨位档（16→3、35→5、45→8、55→12、100→20、130→30、150→40A、180→40B） |

所以「一干一定是容间、二干一定是吨位」只是常见情况，不是硬规则。哪个月一干带了吨位列、
或者二干没带吨位列，脚本都会跟着数据走，不需要改代码。

**吨位口径下备注优先。** 备注写「两辆12吨的车合并一辆30吨的车」「调度通知按30吨结算」
「合并一辆40A的车」的，整行按备注里的吨位算；没写备注的，按这辆车在这条路线跑过的最低档算。
吨位档以当月数据为准，二干模板里 40 与 40A 合并显示为「40（40A）」。

**客户确认的结算吨位优先于容间推算。** 个别趟按容间推出来的档和实际结算不一致时，客户
确认过的口径登记在脚本顶部 `_CONFIRMED_SETTLEMENTS`（按「邮路关键字 + 车牌 + 日期」匹配，
如「西安-陇南 苏E6W073 2026-09-08 按3吨结算」）。**只对确认过的那一趟生效**，同车其他日期、
其他邮路都不受影响；备注里另有明确写法的，仍以备注为准。问题清单会写明哪几趟是按客户确认
修正的，不静默改数。一干/二干归属仍完全按财务收入表的「邮路级别」走，不在这里写死。

**没有吨位时，按容间区间：**

| 容间（m³） | 表头档位 |
|---|---|
| < 55 | 小于55 |
| 55 – 100 | [55,100) |
| 100 – 130 | [100,130) |
| 130 – 150 | [130,150) |
| 150 – 180 | [150,180) |
| ≥ 180 | 大于180 |

- 180 整按「大于180」处理。
- 容间为空的记录不参与出表，会在诊断信息里体现。

**必须说清楚。** 脚本会在问题清单第三块写明「本月这张表有没有吨位列、按什么分档」，
返回 JSON 的 `tier_source` / `outputs[].tier_source` 也有；汇报时按原意转述，不要省略。

## 各字段怎么来的

| 字段 | 来源 |
|---|---|
| 邮路名称 | 基础报表「邮路名称」（两列同名时取后一列标准邮路） |
| 趟次 | 同邮路 + 同档位的基础报表行数 |
| 装载量 | 这些行「运输量 / 邮运量」求和 |
| 运费 | 这些行「运价」求和（运价是每趟已算好的运费总额） |
| 结算收入 | 财务表「结算收入 − 普服收入」，按车牌 + 日期逐趟配对 |
| 盈亏值 | 结算收入 − 运费 |

收入配对：车牌+日期完全一致 → 条数相等按日期顺序一一对应 → 7 天内最近日期贪心。
反向路线（`xx-西安`）不参与配对，按官方口径并入正向路线。

## 一干/二干归属

以财务收入表的「邮路级别」为准，基础报表 sheet 名只是兜底。归属只影响行放在哪张表，
不影响两边的总趟次和总运费。改判的邮路只写在它归入的那张表的问题清单里。

## 停下来的情况

| status | 含义 | 怎么跟用户说 |
|---|---|---|
| `month_mismatch` | 基础报表的业务日期比目标月旧，文件没更新 | 原样转述 message，不要换文件硬跑 |
| `unreadable_base` | 缺少必要列 | 把缺的列名说清楚，请用户补表 |
| `empty_base` | 一行有效数据都没读到 | 请用户确认文件对不对 |
| `finance_mismatch` | 一半以上派车记录配不上收入，两份文件很可能不是同月 | 请用户确认两份文件是不是同一个月的 |
| `output_exists` | 输出目录已有这个月的盈亏表 | 先问用户；确认覆盖带 `--force`，否则换输出目录 |

月份规则：数据月份比目标月**新**（文件名写错）时照常出表，`month_note` 会说明实际用的是哪个月。
