# 邮局月度委办运输报表 — 需求与流程

本文件是 `post-office-agent-v6-source`（AgentOS Skill 包）的需求与流程总览。
脚本口径以 `references/reconciliation-rules.md` 为准；本文说明「要交付什么、输入什么、怎么跑」。

---

## 一、要交付什么

每月一套，共 5 个文件：

| # | 交付件 | 生成脚本 | 说明 |
|---|---|---|---|
| ① | `N月_01_车型汇总表.xlsx` | `build_model_summary` | 草滩 + 港务在线测量表当月记录合并 |
| ② | `N月_02_基础报表初版.xlsx` | `run_workflow --phase review` | 21 列 + 颜色标记 + 问题汇总，**必须人工核对** |
| ③ | `N月_03_基础报表拆分版.xlsx` | `run_workflow --phase final` | 按路线 × 承运公司拆成约 100 个 Sheet |
| ④ | `N月_04_一干盈亏表.xlsx` | `build_profit_tables` | 一干委办运输盈亏 |
| ⑤ | `N月_04_二干盈亏表.xlsx` | `build_profit_tables` | 二干委办运输盈亏 |

## 二、输入文件（含客户别名）

`inspect_inputs.py` 按**表结构**识别角色，不只看文件名。下表列出客户常见的叫法：

| 角色 | 客户常见文件名 | 必需字段 |
|---|---|---|
| 草滩在线测量表 | `草滩在线表.xlsx` | 日 Sheet（如 `8月1日`）、邮路、车牌、挂车、长宽高、容积 |
| 港务在线测量表 | `港务在线表.xlsx` | 日 Sheet（如 `8.1`）、同上 |
| 车管基础数据 | 6 家公司各一个 xlsx | 邮路名称、执行日期、派车单号、车牌、挂车、邮运量、结算吨位 |
| **财务收入表** | **`2026.08运输局.xlsx`** / `2026.03财务收入表.xlsx` | 邮路级别、自委办、往返、邮路名称、流水号、结算收入、普服收入 |
| 一干价格表 | `2024年10月新一干价格表(1).xlsx` | 路线、公里、吨位、容积下限、系数、标准价 |
| 二干价格表 | `二干运费价.xlsx` | 同上 |
| 基础报表初版模板 | `基础报表初版模板.xlsx` | 21 列表头（缺省时用内置 `assets/draft-template.xlsx`） |
| 一干委办盈亏模板 | `一干委办盈亏.xlsx` | 月份页、7 列吨位分组、路线与合计行 |
| 二干委办盈亏模板 | `二干委办盈亏.xlsx` | 同上 |

> **财务收入表就是「运输局表」。** 客户有时把它命名为 `2026.08运输局.xlsx`，
> 有时叫 `2026.03财务收入表.xlsx`，两种情况都是同一张表：31 列、Sheet 名 `sheet1`，
> 字段完全一致。后文统一称**财务收入表**。

## 三、术语

| 术语 | 含义 |
|---|---|
| 一干 / 二干 | 一级干线 / 二级干线，由邮路级别和价格表判定 |
| 基础报表原版 | 客户给的基础报表，必须含 `一干汇总`、`二干基础` 两个 Sheet |
| 结算吨位 | 实际结算用的吨位档。**不是**基础报表的 `吨位` 列（那是车型档） |
| 归桶 | 把一趟的收入计到某个吨位档的列里 |
| 反向路线 | `银川-西安`、`榆林-西安` 这类返程，收入并入对应正向路线 |
| 孤儿记录 | 财务收入表里有、但车牌在基础报表没有派车记录的记录 |

## 四、两条流程

```
完整月度流程（9 类源文件，走 run-state 两阶段）
  草滩/港务在线表 ─┐
  车管数据(6家)  ─┼─► ① 车型汇总表 ─► ② 基础报表初版 ─► ⛔ 人工核对
  一干/二干价格表 ─┘                                        │
  财务收入表 ───────────────────────────────────────────────┤
  盈亏模板 ─────────────────────► ③ 拆分版 ◄────────────────┤
                                 ④⑤ 一干/二干盈亏表 ◄───────┘

独立盈亏表流程（只要 2 份源文件，不依赖 run-state）
  基础报表原版 + 财务收入表 ─► ④⑤ 一干/二干盈亏表
```

两条路径共用同一套盈亏口径：**趟次/装载量/运费来自基础报表的「一干汇总」「二干基础」，
结算收入来自财务收入表逐趟分摊**。

## 五、完整月度流程

### 阶段一：预检 + 初版（`run_workflow.py --phase review`）

```bash
set PYTHONIOENCODING=utf-8
set PYTHONUTF8=1
python scripts/run_workflow.py --phase review --workspace <工作区> --month 2026-08 \
    --bundle-root <skill 根目录>
```

产出：

- `<工作区>/8月_01_车型汇总表.xlsx`
- `<工作区>/8月_02_基础报表初版.xlsx`（Sheet：结构发现 / 问题汇总 / 基础报表）
- `<工作区>/run-state.json`（锁定所有输入的 SHA-256）

返回 `phase: awaiting_review` 时**必须停止**，请人工核对颜色行和「问题汇总」。

### ⛔ 人工核对闸门

人工打开初版，修正容间等核对字段，并在「问题汇总」的「处理结果」列标注。
**不得**改变行数、行顺序和车管权威字段（承运单位、派车单号、邮路、执行日期、车牌、挂车）。

### 阶段二：拆分 + 盈亏（`run_workflow.py --phase final`）

```bash
python scripts/run_workflow.py --phase final --workspace <同一工作区> \
    --review-file <工作区>/8月_02_基础报表初版.xlsx --bundle-root <skill 根目录>
```

- 必须保留同一工作区的 `run-state.json`；任一锁定文件缺失或变更会阻断。
- 产出 `8月_03_基础报表拆分版.xlsx`、`8月_04_一干盈亏表.xlsx`、`8月_04_二干盈亏表.xlsx`。
- 特殊 Sheet（`二干基础`、`一干汇总`）按分类生成；`两趟合一趟` 只在修订初版备注含
  「两辆」「两趟合一趟」「合并为一辆」时才生成，否则列入 `warnings` 由人工补齐。

## 六、独立盈亏表流程（只给两份文件时用）

当客户直接给「基础报表原版」+「财务收入表」，不需要重跑整套流程时使用。
**这两份源文件是第一基准**，盈亏模板只是可选的版式参考。

### 输入

| 输入 | 必需 | 说明 |
|---|:--:|---|
| 基础报表原版 | 是 | 必须含 `一干汇总`、`二干基础` 两个 Sheet |
| 财务收入表 | 是 | 表头第 1 行，31 列标准格式；客户可能命名为 `YYYY.MM运输局.xlsx` |
| 盈亏模板目录 | 否 | 传了只追加「当月无数据的历史路线」占位行 |

### 执行

```bash
python scripts/build_profit_tables.py \
    --base    8月基础报表原版.xlsx \
    --finance 2026.08运输局.xlsx \
    --month   2026-08 \
    --out     <输出目录>
```

可选参数：`--tpl-dir <目录>` 追加模板占位路线；`--no-template-routes` 只输出当月实际路线。

### 第 1 步 读基础报表（行来源）

`_read_summary_sheets()` 只读两个 Sheet：

| Sheet | 判定的级别 |
|---|---|
| `一干汇总` | 一干 |
| `二干基础` | 二干 |

跳过条件：第一列不是整数（标题行、合计行、空行）。每行提取 **邮路名称、车牌号、吨位、运输量、运价、封车时间、备注**。

**吨位按「结算档」归类，不直接用 `吨位` 列**：

1. 备注写「调度通知按 30 吨结算」「两辆12吨车合并为一辆30吨车」→ 该行整行归类为 **30 吨**；
2. 备注没有标记 → 按该车在该路线跑过的**最低吨位档**归类。

基础报表的 `吨位` 列是按容间算出的**车辆车型档**，不等于结算档。8 月一干 40A/40B 共 66 行
全部备注「按30吨结算」，因此整行计入 30 吨档，一干最终只有 12 / 20 / 30 三档。

同时产出两份数据：

- **聚合表** `base[(级别, 路线, 结算吨位)] = [趟次, 装载量, 运费]` → 填表的数字
- **趟次清单** `trips[]`（已带结算吨位）→ 与财务记录配对用

路线先经 `normalize_route()` 标准化：去括号后缀 → 业务后缀（陕临/陕T/港/旺临/提速/特快）→ `废+日期` → `西安草滩-`/`西安航站-` 前缀。

### 第 2 步 读财务收入表（收入来源）

`_read_finance()` 的过滤条件只有两条：

```
邮路级别 含「一干」或「二干」
自委办 = 委办
```

每条记录算 **净额 = 结算收入 − 普服收入**，然后分三类：

| 情况 | 处理 |
|---|---|
| 邮路名称以 `-西安` 结尾（反向路线） | 单独收集，不进配对池 |
| 正常记录 | 建索引：`(车牌, MMDD)` 和 `车牌` |
| 车牌不在基础报表里 | 留给第 5 步的孤儿规则 |

**额定吨位、实载重量一律不读。**

### 第 3 步 逐趟配对（车牌优先）

`allocate_income()` / `_trip_level_income()` 按车牌分组、一对一配，每趟最多用一条记录、每条最多给一趟：

| 轮次 | 规则 |
|---|---|
| 1 | 车牌 + MMDD 精确配对 |
| 2 | 同一车牌两侧剩余条数相等 → 按日期排序一一对应 |
| 3 | 条数不等 → 按日期差从小到大贪心配对（上限 7 天） |

第 2 轮是关键：同一辆车每天跑一趟时，财务流水号常比派车日晚一天，直接按日期差贪心会级联错配。
8 月实测把「6 趟漏配 + 7 条未用」降到「0 趟漏配 + 1 条未用」。

### 第 4 步 收入归桶

`_bucket_income()`：按第 1 步已经归好的**结算吨位**直接汇总，不再做二次归桶。

8 月「西安-深圳」4 辆车跑 30 吨和 40B，40B 的 7 趟备注全是「按30吨结算」，所以整行归 30 吨档：

| 档位 | 趟次 | 运费（元） | 收入（元） |
|---|---:|---:|---:|
| 12 吨 | 2 | 11,163.60 | 14,420.48 |
| 30 吨 | 30 | 265,800.00 | 238,391.36 |

原来的 40B 列不再出现。

### 第 5 步 两处补充归集

1. **反向路线**（`_apply_reverse_income()`）：`银川-西安` 这类收入并入正向路线的最高档。
   8 月只有 `西安-兴平 84.22`、`西安-泾阳 400.83`。
2. **孤儿记录**：车牌在基础报表无派车记录、但出现在当月财务收入表 → **按「出现在当月就计当月」处理**，
   归入该路线现有最高档。8 月即 `蒙A06L37` 的 174.42 元，归到「西安-呼和」30 吨档。
   路线当月不存在时跳过并列入告警，不得丢弃。

### 第 6 步 吨位档合并与写表

`_merge_tiers()` 先定档：一干 `40A` / `40B` 分列；二干 `40` 和 `40A` 合并成 `40（40A）`。

`_write()` 按官方版式输出：

```
第 1 行   标题（合并单元格）
第 2 行   吨位档名（每档合并 7 列）+ 右侧 4 个汇总列
第 3 行   子表头：趟次/装载量/每车平均装载量/运费/结算收入/盈亏/平均每车盈亏
第 4+ 行  路线明细
合计行    各档汇总 + SUM 公式
空 2 行
环比区    上月 / 本月 / 环比
```

### 校验闭环

生成后必须对上四个数：

| 校验项 | 8 月结果 |
|---|---|
| 一干趟次 = `一干汇总` 数据行数 | 703 [OK] |
| 二干趟次 = `二干基础` 数据行数 | 1651 [OK] |
| 一干收入 = 财务收入表一干委办净额 | 2,532,240.78 [OK] |
| 二干收入 = 财务收入表二干委办净额 | 1,147,573.01 [OK] |

任一项不等，说明配对或归集有遗漏，不得直接交付。

### 口径

| 报表列 | 来源 |
|---|---|
| 趟次、装载量、运费 | `一干汇总` / `二干基础`，按（标准邮路，**结算吨位**）聚合 |
| **吨位（分档依据）** | 基础报表 `备注` 优先（「按30吨结算」→30 吨）；无备注取该车该路线**最低档** |
| 结算收入 | 财务收入表 `自委办=委办`，逐趟按（车牌 + 流水号前 4 位 MMDD）一对一分摊；无派车记录的按路线归入最高档 |
| 盈亏 | 结算收入 − 运费 |
| 路线顺序 | 当月数据出现顺序 |

**财务收入表里的「额定吨位」「实载重量（吨）」一律不读，不参与分档。**
二者都不是吨位档的依据：

- `额定吨位` 是录入的车型口径，与基础报表经常不一致。例：`西安草滩-内江` 财务收入表写 20、
  基础报表是 30；实测委办行里只有 28/2378 条两者相同。
- `实载重量（吨）` 是每趟实际装货量（分布 0～21 吨）。20 吨的车本次只装 6.3 吨，
  拿它分档会把整列车压进最低档；实测按它分档准确率从 83% 掉到 6%。

**行数守恒**：一干合计 = `一干汇总` 数据行数；二干合计 = `二干基础` 数据行数。
`两趟合一趟`、`降吨位` 等特殊 Sheet 已包含在内，不重复计入。

### 五个容易踩的点

1. **财务收入表「流水号」前 4 位是日期（MMDD）**，不是序号。它通常比派车日晚一天（次日结算）。
   兜底配对按日期差从小到大贪心分配，每趟最多用一条记录、每条记录最多给一趟。
   **但跨月记录按「是否出现在本月财务收入表」判定，不看流水号日期**：只要该行在当月表里
   就属于当月，必须计入。车牌本月无派车记录、无法逐趟配对时，按邮路名称归到该路线现有
   最高吨位档（8 月 `蒙A06L37` 的 7/31 记录 174.42 元即按此计入「西安-呼和」30 吨档）。
2. **二干 40 吨档要合并**：基础报表里 `40` 和 `40A` 是两个值，官方表把它们合成一组「40（40A）」。
   一干的 `40A` / `40B` 保持分列。
3. **反向路线要并入正向**：`银川-西安`、`榆林-西安`、`汉中-西安`、`宝鸡-西安` 这类反向路线的
   委办收入计入对应的正向路线，放在该路线最高的吨位档。一干、二干都适用
   （3 月一干「西安-银川」官方总额 659,221.14 = 归桶 590,882.77 + 反向 68,338.52）。
4. **吨位归类看备注**：备注写「调度通知按30吨结算」「两辆12吨车合并为一辆30吨车」的，
   该行整行（趟次、装载量、运费、收入）归 30 吨档；**备注没有标记时，按该车该路线的最低档**。
   基础报表的 `吨位` 列是车型档，不等于结算档。8 月一干 40A/40B 共 66 行全部备注
   「按30吨结算」，所以最终只输出 12 / 20 / 30 三档。
5. **吨位档名称跟随当月价格表，不写死**：价格表每月会给档位名（如某月 16m³ 档写「2.75吨」，
   下月可能写「3吨」），基础报表的 `吨位` 列就是按当月价格表生成的。表头直接用当月实际值，
   不得沿用历史档名，也不得在代码里硬编码任何档位名。

### 输出 JSON 与汇报

脚本末尾输出 JSON，汇报只依据这些字段：

| 字段 | 含义 | 处理要求 |
|---|---|---|
| `income_match.exact/near/miss` | 精确匹配 / 兜底匹配 / 未匹配趟次 | `miss>0` 必须告知用户具体趟次 |
| `tonnage_groups` | 实际输出的吨位档 | 直接汇报 |
| `unmatched_samples` | 未匹配明细 | 不得用估算值补足金额 |
| `routes` / `placeholder_routes` | 路线数 / 占位路线数 | 占位行无当月数据，需说明 |

**3 月官方表不能用来验证「备注归类」规则。** 3 月官方表是按基础报表 `吨位` 列分组
（一干 40A 231 趟、40B 251 趟原样保留），没有按备注改档。按现在确认的备注口径重算后，
3 月一干逐格精确率会从 90% 掉到 47%——这是**口径不同**，不是算错。

当前口径没有官方成品可比对，交付时只保证「校验闭环」那四个数。
汇报时不得宣称与历史官方表逐格一致。

> **回归基线只有 3 月有效。** `数据/委办报表开发/4月`、`5月` 目录下的 `一干委办盈亏.xlsx` /
> `二干委办盈亏.xlsx` 与 3 月文件完全相同（SHA-256 一致），里面并无 4/5 月官方成品，
> 不能用来做准确率回归。比对时只取与目标月份同名的工作表（`26年3月` / `3月`），
> 不要取工作簿第一张表。

## 八、环境要求

- Python 3.12，依赖仅 `openpyxl`（离线打包，`check_runtime.py` 会做 xlsx 往返测试）。
- Windows 控制台必须设 `PYTHONIOENCODING=utf-8` 和 `PYTHONUTF8=1`，否则中文输出乱码。
- 脚本内不使用 emoji，统一用 `[OK]` / `[STOP]`。
- **Excel 打开文件时不要覆盖**，会写失败。
- 输入在 `/workspace`，输出写 `/workspace/output`；不要用 `/inputs`、`/outputs`。
