# 邮局月度委办运输报表 — 需求与流程

本文件是 `post-office-agent-v6-source`（AgentOS Skill 包）的需求与流程总览。
脚本口径以 `references/reconciliation-rules.md` 为准；本文说明「要交付什么、输入什么、怎么跑」。

---

## 一、要交付什么

每月一套，共 5 个文件：

| # | 交付件 | 生成脚本 | 说明 |
|---|---|---|---|
| ① | `N月_01_车型汇总表.xlsx` | `build_model_summary` | 草滩 + 港务在线测量表当月记录合并 |
| ② | `N月_02_基础报表初版.xlsx` | `run_workflow --phase review` | 21 列 + 颜色标记 + 问题汇总，**必须人工核对** |
| ③ | `N月_03_基础报表拆分版.xlsx` | `run_workflow --phase final` | 按路线 × 承运公司拆成约 100 个 Sheet |
| ④ | `N月_04_一干盈亏表.xlsx` | `build_profit_tables` | 一干委办运输盈亏 |
| ⑤ | `N月_04_二干盈亏表.xlsx` | `build_profit_tables` | 二干委办运输盈亏 |

## 二、输入文件（含客户别名）

`--phase detect`（`scripts/reconciliation/detect.py`）按**表结构**识别文件角色，不看文件名。
文件名只在结构无法区分时作兜底。

| 角色 | 客户常见文件名 | 识别依据（表结构） |
|---|---|---|
| 草滩在线测量表 | `草滩在线表.xlsx` | 日 Sheet 命名为 `8月1日`；邮路、车牌、挂车、长宽高、容积 |
| 港务在线测量表 | `港务在线表.xlsx` | 日 Sheet 命名为 `8.1`；字段同上 |
| 车管基础数据 | 6 家公司各一个 xlsx | 邮路名称、邮路执行日期、派车单号、车牌、挂车、邮运量、结算吨位 |
| **财务收入表** | **`2026.08运输局.xlsx`** / `2026.03财务收入表.xlsx` | 表头含 邮路名称 + 结算收入 + 普服收入 |
| 一干价格表 | `2024年10月新一干价格表(1).xlsx` | 表头含 路线/路向 + 公里 + 吨位/系数；表内标题或文件名标注「一干」 |
| 二干价格表 | `二干运费价.xlsx` | 同上，标注「二干」 |
| 基础报表原版 | `8月基础报表原版.xlsx` | 含 Sheet `一干汇总` 或 `二干基础` |
| 基础报表初版模板 | `基础报表初版模板.xlsx` | 21 列表头完全匹配（缺省时用内置 `assets/draft-template.xlsx`） |
| 一干委办盈亏模板 | `一干委办盈亏.xlsx` | 含 7 列吨位分组子表头；标题或文件名标注「一干」 |
| 二干委办盈亏模板 | `二干委办盈亏.xlsx` | 同上，标注「二干」 |

> **财务收入表就是「运输局表」。** 客户有时把它命名为 `2026.08运输局.xlsx`，
> 有时叫 `2026.03财务收入表.xlsx`，两种情况都是同一张表：31 列、Sheet 名 `sheet1`，
> 字段完全一致。后文统一称**财务收入表**。

### 识别不出来时的处理

| 情况 | 脚本行为 | 处理方式 |
|---|---|---|
| 价格表/盈亏模板的表内标题和文件名都没有一干/二干 | 返回 `price_candidate` / `profit_candidate`，置信度 `low` | 停下问用户，不按档位名猜 |
| 草滩/港务日 Sheet 命名方式相同 | 保留一个角色，置信度 `low` | 汇报时请用户确认站点 |
| 文件月份与目标月不一致 | 角色保留，置信度 `low` | 正常流程会跳过；盈亏表流程会提示 |
| 缺角色 / 同角色多文件 | `missing` / `ambiguous` | 停下问用户，不自行挑选 |

档位名不能用来区分一干/二干：一干 2025 版模板有 `7.5米 45方 8吨` 档，
二干 2026 版价格表有 `40吨B` 档。唯一可靠的线索是表内标题或文件名里的「一干/二干」。

## 三、术语

| 术语 | 含义 |
|---|---|
| 一干 / 二干 | 一级干线 / 二级干线，由邮路级别和价格表判定 |
| 基础报表原版 | 客户给的基础报表，必须含 `一干汇总`、`二干基础` 两个 Sheet |
| 结算吨位 | 实际结算用的吨位档。**不是**基础报表的 `吨位` 列（那是车型档） |
| 归桶 | 把一趟的收入计到某个吨位档的列里 |
| 反向路线 | `银川-西安`、`榆林-西安` 这类返程，收入并入对应正向路线 |
| 孤儿记录 | 财务收入表里有、但车牌在基础报表没有派车记录的记录 |

## 四、两条流程

```
完整月度流程（9 类源文件，走 run-state 两阶段）
  草滩/港务在线表 ─┐
  车管数据(6家)  ─┼─► ① 车型汇总表 ─► ② 基础报表初版 ─► ⛔ 人工核对
  一干/二干价格表 ─┘                                        │
  财务收入表 ───────────────────────────────────────────────┤
  盈亏模板 ─────────────────────► ③ 拆分版 ◄────────────────┤
                                 ④⑤ 一干/二干盈亏表 ◄───────┘

独立盈亏表流程（只要 2 份源文件，不依赖 run-state）
  基础报表原版 + 财务收入表 ─► ④⑤ 一干/二干盈亏表
```

两条路径共用同一套盈亏口径：**趟次/装载量/运费来自基础报表的「一干汇总」「二干基础」，
结算收入来自财务收入表逐趟分摊**。

## 五、完整月度流程

### 阶段一：预检 + 初版（`run_workflow.py --phase review`）

```bash
set PYTHONIOENCODING=utf-8
set PYTHONUTF8=1
python scripts/agentos_entrypoint.py --phase detect --task review --workspace <工作区> --month 2026-08
python scripts/run_workflow.py --phase review --workspace <工作区> --month 2026-08 \
    --bundle-root <skill 根目录>
```

先跑 `detect`，确认 `resolved` 里 9 类文件都唯一命中；出现 `missing` / `ambiguous` 时先问用户，
不要直接跑 `review`。

产出：

- `<工作区>/8月_01_车型汇总表.xlsx`
- `<工作区>/8月_02_基础报表初版.xlsx`（Sheet：结构发现 / 问题汇总 / 基础报表）
- `<工作区>/run-state.json`（锁定所有输入的 SHA-256）

返回 `phase: awaiting_review` 时**必须停止**，请人工核对颜色行和「问题汇总」。

### ⛔ 人工核对闸门

人工打开初版，修正容间等核对字段，并在「问题汇总」的「处理结果」列标注。
**不得**改变行数、行顺序和车管权威字段（承运单位、派车单号、邮路、执行日期、车牌、挂车）。

### 阶段二：拆分 + 盈亏（`run_workflow.py --phase final`）

```bash
python scripts/run_workflow.py --phase final --workspace <同一工作区> \
    --review-file <工作区>/8月_02_基础报表初版.xlsx --bundle-root <skill 根目录>
```

- 必须保留同一工作区的 `run-state.json`；任一锁定文件缺失或变更会阻断。
- 产出 `8月_03_基础报表拆分版.xlsx`、`8月_04_一干盈亏表.xlsx`、`8月_04_二干盈亏表.xlsx`。
- 特殊 Sheet（`二干基础`、`一干汇总`）按分类生成；`两趟合一趟` 只在修订初版备注含
  「两辆」「两趟合一趟」「合并为一辆」时才生成，否则列入 `warnings` 由人工补齐。

## 六、独立盈亏表流程（只给两份文件时用）

当客户直接给「基础报表原版」+「财务收入表」，不需要重跑整套流程时使用。
**这两份源文件是第一基准**，盈亏模板只是可选的版式参考。

### 输入

| 输入 | 必需 | 说明 |
|---|:--:|---|
| 基础报表原版 | 是 | 必须含 `一干汇总`、`二干基础` 两个 Sheet |
| 财务收入表 | 是 | 表头第 1 行，31 列标准格式；客户可能命名为 `YYYY.MM运输局.xlsx` |
| 盈亏模板目录 | 否 | 传了只追加「当月无数据的历史路线」占位行 |

### 执行

推荐走统一入口，不传文件名，由脚本按表结构自动识别：

```bash
python scripts/agentos_entrypoint.py --phase profit \
    --workspace <工作区> --month 2026-08
```

需要显式指定时（例如工作区里有多份同角色文件）：

```bash
python scripts/agentos_entrypoint.py --phase profit \
    --base-file <基础报表原版> \
    --finance-file <财务收入表> \
    --workspace <工作区> --month 2026-08
```

也可以直接调用底层脚本：

```bash
python scripts/build_profit_tables.py \
    --base    <基础报表原版> \
    --finance <财务收入表> \
    --month   2026-08 \
    --out     <输出目录>
```

可选参数：`--tpl-dir <目录>` 追加模板占位路线；`--no-template-routes` 只输出当月实际路线。

### 第 1 步 读基础报表（行来源）

`_read_summary_sheets()` 只读两个 Sheet：

| Sheet | 判定的级别 |
|---|---|
| `一干汇总` | 一干 |
| `二干基础` | 二干 |

跳过条件：第一列不是整数（标题行、合计行、空行）。每行提取 **邮路名称、车牌号、吨位、运输量、运价、封车时间、备注**。

**吨位按「结算档」归类，不直接用 `吨位` 列**：

1. 备注写「调度通知按 30 吨结算」「两辆12吨车合并为一辆30吨车」→ 该行整行归类为 **30 吨**；
2. 备注没有标记 → 按该车在该路线跑过的**最低吨位档**归类。

基础报表的 `吨位` 列是按容间算出的**车辆车型档**，不等于结算档。8 月一干 40A/40B 共 66 行
全部备注「按30吨结算」，因此整行计入 30 吨档，一干最终只有 12 / 20 / 30 三档。

同时产出两份数据：

- **聚合表** `base[(级别, 路线, 结算吨位)] = [趟次, 装载量, 运费]` → 填表的数字
- **趟次清单** `trips[]`（已带结算吨位）→ 与财务记录配对用

路线先经 `normalize_route()` 标准化：去括号后缀 → 业务后缀（陕临/陕T/港/旺临/提速/特快）→ `废+日期` → `西安草滩-`/`西安航站-` 前缀。

### 第 2 步 读财务收入表（收入来源）

`_read_finance()` 的过滤条件只有两条：

```
邮路级别 含「一干」或「二干」
自委办 = 委办
```

每条记录算 **净额 = 结算收入 − 普服收入**，然后分三类：

| 情况 | 处理 |
|---|---|
| 邮路名称以 `-西安` 结尾（反向路线） | 单独收集，不进配对池 |
| 正常记录 | 建索引：`(车牌, MMDD)` 和 `车牌` |
| 车牌不在基础报表里 | 留给第 5 步的孤儿规则 |

**额定吨位、实载重量一律不读。**

### 第 3 步 逐趟配对（车牌优先）

`allocate_income()` / `_trip_level_income()` 按车牌分组、一对一配，每趟最多用一条记录、每条最多给一趟：

| 轮次 | 规则 |
|---|---|
| 1 | 车牌 + MMDD 精确配对 |
| 2 | 同一车牌两侧剩余条数相等 → 按日期排序一一对应 |
| 3 | 条数不等 → 按日期差从小到大贪心配对（上限 7 天） |

第 2 轮是关键：同一辆车每天跑一趟时，财务流水号常比派车日晚一天，直接按日期差贪心会级联错配。
8 月实测把「6 趟漏配 + 7 条未用」降到「0 趟漏配 + 1 条未用」。

### 第 4 步 收入归桶

`_bucket_income()`：按第 1 步已经归好的**结算吨位**直接汇总，不再做二次归桶。

8 月「西安-深圳」4 辆车跑 30 吨和 40B，40B 的 7 趟备注全是「按30吨结算」，所以整行归 30 吨档：

| 档位 | 趟次 | 运费（元） | 收入（元） |
|---|---:|---:|---:|
| 12 吨 | 2 | 11,163.60 | 14,420.48 |
| 30 吨 | 30 | 265,800.00 | 238,391.36 |

原来的 40B 列不再出现。

### 第 5 步 两处补充归集

1. **反向路线**（`_apply_reverse_income()`）：`银川-西安` 这类收入并入正向路线的最高档。
   8 月只有 `西安-兴平 84.22`、`西安-泾阳 400.83`。
2. **孤儿记录**：车牌在基础报表无派车记录、但出现在当月财务收入表 → **按「出现在当月就计当月」处理**，
   归入该路线现有最高档。8 月即 `蒙A06L37` 的 174.42 元，归到「西安-呼和」30 吨档。
   路线当月不存在时跳过并列入告警，不得丢弃。

### 第 6 步 吨位档合并与写表

`_merge_tiers()` 先定档：一干 `40A` / `40B` 分列；二干 `40` 和 `40A` 合并成 `40（40A）`。

`_write()` 按官方版式输出：

```
第 1 行   标题（合并单元格）
第 2 行   吨位档名（每档合并 7 列）+ 右侧 4 个汇总列
第 3 行   子表头：趟次/装载量/每车平均装载量/运费/结算收入/盈亏/平均每车盈亏
第 4+ 行  路线明细
合计行    各档汇总 + SUM 公式
空 2 行
环比区    上月 / 本月 / 环比
```

### 校验闭环

生成后必须对上四个数：

| 校验项 | 8 月结果 |
|---|---|
| 一干趟次 = `一干汇总` 数据行数 | 703 [OK] |
| 二干趟次 = `二干基础` 数据行数 | 1651 [OK] |
| 一干收入 = 财务收入表一干委办净额 | 2,532,240.78 [OK] |
| 二干收入 = 财务收入表二干委办净额 | 1,147,573.01 [OK] |

任一项不等，说明配对或归集有遗漏，不得直接交付。

### 口径

| 报表列 | 来源 |
|---|---|
| 趟次、装载量、运费 | `一干汇总` / `二干基础`，按（标准邮路，**结算吨位**）聚合 |
| **吨位（分档依据）** | 基础报表 `备注` 优先（「按30吨结算」→30 吨）；无备注取该车该路线**最低档** |
| 结算收入 | 财务收入表 `自委办=委办`，逐趟按（车牌 + 流水号前 4 位 MMDD）一对一分摊；无派车记录的按路线归入最高档 |
| 盈亏 | 结算收入 − 运费 |
| 路线顺序 | 当月数据出现顺序 |

**财务收入表里的「额定吨位」「实载重量（吨）」一律不读，不参与分档。**
二者都不是吨位档的依据：

- `额定吨位` 是录入的车型口径，与基础报表经常不一致。例：`西安草滩-内江` 财务收入表写 20、
  基础报表是 30；实测委办行里只有 28/2378 条两者相同。
- `实载重量（吨）` 是每趟实际装货量（分布 0～21 吨）。20 吨的车本次只装 6.3 吨，
  拿它分档会把整列车压进最低档；实测按它分档准确率从 83% 掉到 6%。

**行数守恒**：一干合计 = `一干汇总` 数据行数；二干合计 = `二干基础` 数据行数。
`两趟合一趟`、`降吨位` 等特殊 Sheet 已包含在内，不重复计入。

### 五个容易踩的点

1. **财务收入表「流水号」前 4 位是日期（MMDD）**，不是序号。它通常比派车日晚一天（次日结算）。
   兜底配对按日期差从小到大贪心分配，每趟最多用一条记录、每条记录最多给一趟。
   **但跨月记录按「是否出现在本月财务收入表」判定，不看流水号日期**：只要该行在当月表里
   就属于当月，必须计入。车牌本月无派车记录、无法逐趟配对时，按邮路名称归到该路线现有
   最高吨位档（8 月 `蒙A06L37` 的 7/31 记录 174.42 元即按此计入「西安-呼和」30 吨档）。
2. **二干 40 吨档要合并**：基础报表里 `40` 和 `40A` 是两个值，官方表把它们合成一组「40（40A）」。
   一干的 `40A` / `40B` 保持分列。
3. **反向路线要并入正向**：`银川-西安`、`榆林-西安`、`汉中-西安`、`宝鸡-西安` 这类反向路线的
   委办收入计入对应的正向路线，放在该路线最高的吨位档。一干、二干都适用
   （3 月一干「西安-银川」官方总额 659,221.14 = 归桶 590,882.77 + 反向 68,338.52）。
4. **吨位归类看备注**：备注写「调度通知按30吨结算」「两辆12吨车合并为一辆30吨车」的，
   该行整行（趟次、装载量、运费、收入）归 30 吨档；**备注没有标记时，按该车该路线的最低档**。
   基础报表的 `吨位` 列是车型档，不等于结算档。8 月一干 40A/40B 共 66 行全部备注
   「按30吨结算」，所以最终只输出 12 / 20 / 30 三档。
5. **吨位档名称跟随当月价格表，不写死**：价格表每月会给档位名（如某月 16m³ 档写「2.75吨」，
   下月可能写「3吨」），基础报表的 `吨位` 列就是按当月价格表生成的。表头直接用当月实际值，
   不得沿用历史档名，也不得在代码里硬编码任何档位名。

### 输出 JSON 与汇报

脚本末尾输出 JSON，汇报只依据这些字段：

| 字段 | 含义 | 处理要求 |
|---|---|---|
| `income_match.exact/near/miss` | 精确匹配 / 兜底匹配 / 未匹配趟次 | `miss>0` 必须告知用户具体趟次 |
| `tonnage_groups` | 实际输出的吨位档 | 直接汇报 |
| `unmatched_samples` | 未匹配明细 | 不得用估算值补足金额 |
| `routes` / `placeholder_routes` | 路线数 / 占位路线数 | 占位行无当月数据，需说明 |

**3 月官方表不能用来验证「备注归类」规则。** 3 月官方表是按基础报表 `吨位` 列分组

### 输入不全时的返回契约（v6.2.2 起）

只上传了个别文件时，脚本**不抛异常、不返回非零退出码**；返回正常 JSON，
由 Agent 请用户补齐文件：

```json
{
  "ok": true,
  "status": "needs_input",
  "phase": "awaiting_inputs",
  "missing_inputs": [
    {"kind": "missing", "role": "vehicle", "label": "车管基础数据",
     "required": 6, "found": 0,
     "action": "请上传车管基础数据（需要 6 个，当前识别到 0 个）"}
  ],
  "message": "当前上传的文件不完整，需要补充或确认：车管基础数据。",
  "next_action": "请补充或确认上述文件后重新执行；已识别到的文件会保留。"
}
```

- **退出码 0**；`ok:false` 只用于真正的执行失败（环境、依赖、输出校验）。
- `kind` 取值：`missing` 缺文件 / `ambiguous` 同角色多份 / `unreadable` 打不开 /
  `month_mismatch` 月份不符 / `wrong_location` 文件不在当前任务 /
  `prerequisite` 缺少上一阶段的 run-state。
- 覆盖阶段：`detect`、`inspect`、`summary`、`review`、`final`、`profit`；
  直接调用 `build_model_summary.py` / `build_profit_tables.py` 缺文件时同样返回该结构。
- Agent 应逐条转述 `missing_inputs[].action`，请用户补文件，**不要说成“脚本报错”**。

## 七、入口

```
agentos_entrypoint.py --phase <X>
   ├─ list      → 列出工作区文件（只看文件名，不判断角色）
   ├─ detect    → 按表结构识别每个文件是什么，返回 resolved/missing/ambiguous
   ├─ summary   → build_model_summary.py      （只要车型汇总表；可自动识别两份在线表）
   ├─ review    → run_workflow.py --phase review
   ├─ final     → run_workflow.py --phase final
   ├─ profit    → build_profit_tables.py      （只要盈亏表；可自动识别两份源文件）
   ├─ inspect   → inspect_inputs.py           （预检并写 run-state.json）
   ├─ runtime   → check_runtime.py            （环境自检）
   └─ validate  → validate_outputs.py         （校验已有输出，--stage review|final）
```

`detect` 必须最先跑，`--task` 取 `review` / `summary` / `profit`。
`inspect` 内部复用同一套结构识别，不再按文件名判断草滩/港务。
`profit` 阶段不需要 `run-state.json`，可与完整流程分开、单独重复执行。

### 已知未解决：Windows 上的原生崩溃

读取较大的工作簿（100 Sheet 的基础报表原版、17MB 的财务收入表）时，
进程偶发以 `0xC0000005`（access violation）退出。崩溃点每次都不同，
但都落在 XML 解析或 openpyxl 的 `serialisable.__eq__` 里。

已确认的事实：

- 与业务代码无关：`load_workbook(...)` + 遍历所有 Sheet 就能复现。
- 单独读任何一个工作簿都不崩（各 25—30 次 0 失败），
  只有在**同一进程里反复开关多个工作簿**时才偶发。
- 关闭 lxml 后端能降低概率，但没有消除。

统计（同一台机器，同一组文件）：

| 配置 | 崩溃率 |
|---|---|
| lxml 后端 | 7 / 40 |
| 标准库后端 | 0 / 40 |
| 完整 `--phase final`（标准库后端） | 10 / 20 |

`xml_compat.py` 关掉 lxml 后，完整流程崩溃率从约 25% 降到约 10%—50%（波动很大），
**这不算修好**。根因在 CPython 3.12 + lxml 6.0.0 的原生层，业务代码无法根治。

AgentOS 里入口是通过 `runpy` 在宿主进程内执行的，原生崩溃会连带杀掉宿主。
缓解措施：

- `agentos_entrypoint.py` 支持 `POST_OFFICE_HARD_EXIT=1`，让 CLI 运行跳过解释器收尾；
  默认不开启，避免 `runpy` 场景误杀宿主。
- 测试脚本遇到原生崩溃会自动重跑一次，并打印 `[WARN]`。
- 交付前建议在目标机器上把 `--phase final` 连跑 3 次，全过再交付。

彻底解决需要换环境：改用不含 lxml 的干净 Python 环境，
或升级到已修复该问题的 CPython 小版本。这件事要单独验证，不能靠改业务代码绕过。

`model_rows=3224`、`model_summary_matched=3921`、`model_summary_unmatched=388`、`price_matched=3628`。
若这几个数明显偏离，说明上面的修复被回退了。

   `/outputs`，并在 JSON 的 `published` 里返回文件名。
Windows 上偶发原生崩溃（0xC0000005）时脚本会自动重跑一次并打印 `[WARN]`；
该问题的现状和已知边界见第九节。

## 十一、打包

```bash
python post-office-agent-v6-source/build_packages.py
```

产出三个包到仓库根目录：

- `post-office-monthly-reconciliation-skill.zip`（后台 skill 包，对应 `POST /api/skills/upload`）
- `邮局委办运输报表核对V6.2.agentos.zip`（**AgentOS「导入专家」用这个**）
- `邮局委办运输报表核对V6.2-agent.zip`（`agentos-v1` 导出格式，仅供导出/备份，导入对话框不接受）

`.agentos.zip` 的结构必须是：

```
agent/agent.yaml
agent/prompt.md
agent/skills/post-office-monthly-reconciliation/...
```

只放 `agent.json` 会在导入时报「缺少 agent.yaml」；技能不放在
`agent/skills/<name>/` 下，导入后启动任务会报「绑定技能未安装」。
另外，即使包内带了技能，平台当前版本也不会自动注册到技能列表，
仍需通过 `POST /api/skills/upload` 单独安装一次。

包名与 `manifest.json` 的 `version` 同步，版本号变了包名自动跟着变，不要手改文件名。

脚本会校验 `SKILL.md`、`manifest.json`、`assets/split-report-template.xlsx` 存在，
缺任何一个直接报错。
